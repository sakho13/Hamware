# Planning and Reports — R01・R02

## 当週の計画

EmployeeとDevelopmentTaskは生成時にGuidのIdを持ち、生存期間中は不変。同名でも別の対象として扱う。AddTask / AddEmployeeはnullと同一インスタンスの再登録を無視する。同名の別インスタンスはそれぞれ登録する。復元用のID指定APIは保存機能とともに後続で追加する。

`TryAllocateHours`は正の時間の加算、`TrySetAllocatedHours`は0以上の合計時間の設定を行う。0は該当する社員×タスクの割当だけを取り消す。存在しない割当への0設定は成功するが、未登録・完了済みタスクへの操作は拒否する。

どちらも失敗時は状態不変。必要ならout引数のAllocationFailureから理由を取得できる。減算時の勤務時間返却はEmployeeの内部操作でのみ行い、週の上限を超えて返さない。確定済み週の時間・疲労・進捗の取消は提供しない。

GetAllocationsはId・表示名・整数の実勤務時間だけを持つ読取専用スナップショット。後の編集・週送りで過去の取得結果は変わらない。GetAllocatedHoursは現在の指定ペアの割当時間を返す。

## 週次レポート

AdvanceWeekは、進捗・完了効果・社員の疲労計算を検証し、WeekResultを生成してから反映する。週番号のオーバーフローも反映前に検出する。検証・計算失敗で既存状態・週番号・履歴を部分更新しない。単一スレッドで利用する。

Prepareでは各ドメインが自分の変更結果を一度だけ計算する。Employeeは疲労、DevelopmentTaskは上限制御と完了判定、ProductStateは負債・品質の上下限制御を所有する。Commitは全対象が準備時の状態であることを確認した後、その同じ結果を実状態へ代入する。週報のAfter値と完了判定もこの結果を共有し、週報側で式を再計算しない。直接の内部操作CompleteWeek / ApplyProgress / ApplyChangesも同じ処理を経由して変更結果を返す。

準備された週は一度だけ確定できる。準備後に対象の状態が変わった場合は、どの対象も更新する前に拒否する。Prepare / Commitを直接テストし、検証失敗・再試行・二重確定と実状態との一致を確認する。

WeekResultの内容：

- 対象の週番号（処理後の週番号ではない）。
- 全社員のId・名前・実勤務時間・疲労の前後。無割当社員も含む。
- 当週に処理した未完了タスクのId・名前・種別・必要進捗・前後の進捗・新規完了。
- 社員ごとの実勤務・スキル倍率・疲労倍率・負債倍率・計算進捗。
- 完了上限適用後の進捗と、破棄した超過進捗。超過しても実勤務を返却しない。
- タスクごとの完了効果、およびプロダクト全体の要求増減・上下限適用後の実際の増減。

レポートには可変ドメインオブジェクトや割当辞書を保持せず、リストはコピーして変更不可にする。現在のスキルや進捗が変わっても過去レポートは変わらない。内部精度を丸めない。合計勤務時間はlongで持ち、社員別のintを合計してもオーバーフローさせない。

タスクと社員別寄与は登録順で返す。割当の作成・取消・再設定の順序には依存しない。

Historyは全結果の読取専用ビュー、LastWeekResultは最新結果。現段階はメモリ内のみで永続化・履歴の圧縮は行わない。GameSimulationは画面状態を持たず、連続して週を進められる。

Hamware.GameはUnityEngineに依存しないアセンブリ。内部の状態変更APIはドメインテストだけへ公開し、表示層には公開しない。
