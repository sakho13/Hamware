# Planning and Reports — R01〜R03

## 当週の計画

EmployeeとDevelopmentTaskは生成時にGuidのIdを持ち、生存期間中は不変。同名でも別の対象として扱う。復元用のID指定APIは保存機能とともに後続で追加する。

`TryAllocateHours`は正の時間の加算、`TrySetAllocatedHours`は0以上の合計時間の設定を行う。0は該当する社員×タスクの割当だけを取り消す。存在しない割当への0設定は成功するが、未登録・完了済みタスクへの操作は拒否する。

どちらも失敗時は状態不変。必要ならout引数のAllocationFailureから理由を取得できる。減算時の勤務時間返却はEmployeeの内部操作でのみ行い、週の上限を超えて返さない。確定済み週の時間・疲労・進捗の取消は提供しない。

GetAllocationsはId・表示名・整数の実勤務時間だけを持つ読取専用スナップショット。後の編集・週送りで過去の取得結果は変わらない。GetAllocatedHoursは現在の指定ペアの割当時間を返す。

## 週次レポート

AdvanceWeekは、進捗・完了効果・社員の疲労計算を検証し、WeekResultを生成してから反映する。週番号のオーバーフローも反映前に検出する。検証・計算失敗で既存状態・週番号・履歴を部分更新しない。

WeekResultの内容：

- 対象の週番号（処理後の週番号ではない）。
- 全社員のId・名前・実勤務時間・疲労の前後。無割当社員も含む。
- 当週に処理した未完了タスクのId・名前・種別・必要進捗・前後の進捗・新規完了。
- 社員ごとの実勤務・スキル倍率・疲労倍率・負債倍率・計算進捗。
- 完了上限適用後の進捗と、破棄した超過進捗。超過しても実勤務を返却しない。
- タスクごとの完了効果、およびプロダクト全体の要求増減・上下限適用後の実際の増減。

レポートには可変ドメインオブジェクトや割当辞書を保持せず、リストはコピーして変更不可にする。現在のスキルや進捗が変わっても過去レポートは変わらない。内部精度を丸めない。合計勤務時間はlongで持ち、社員別のintを合計してもオーバーフローさせない。

Historyは全結果の読取専用ビュー、LastWeekResultは最新結果。現段階はメモリ内のみで永続化・履歴の圧縮は行わない。UIでは前週の結果を再表示できる。

## 画面とシナリオ

PrototypeSessionは固定シナリオの開始・再開始と「計画中／週報確認中」を管理する。週報確認中は再度の週送りと割当編集を受け付けない。これはUIの連打防止であり、GameSimulation単体は従来通り連続して週を進められる。

HamwareUIはUnity UI Toolkitで表示・入力・確認ダイアログを担当する。計算式はUIへ置かない。社員の顔はUI要素で描き、疲労60以上で目の表情を変える。職種属性は追加しない。

社員2名、機能4件、Testing2件、Architecture2件の固定タスクで担当変更・休養・改善を試す。すべて完了しても強制終了せず、休養と週送りを続けられる。新しいタスクの生成・依存関係・公開は後続の範囲。

Hamware.unityをPlayするかビルドを起動すると一画面で開始する。表示は1600×1000を基準に拡大縮小する。日本語のOSフォントを利用するため、この試作の対象は日本語フォントがあるWindows環境。R08まで保存機能はなく、再開始は確認ダイアログで保護する。
