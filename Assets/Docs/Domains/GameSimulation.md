# GameSimulation

GameSimulation はゲーム全体のシミュレーション進行を管理します。

- 各シミュレーションが1つの`ProductState`を生成し、`Product`から参照できる。初期値は負債10・品質70で、生成時に指定できる。値域・増減・生産性への影響は[ProductHealth](./ProductHealth.md)を参照。
- 社員とタスクを登録できる。同じ社員インスタンスの再登録は無視し、同名の別インスタンスは登録できる。
- 社員をタスクへ割り当て、工数を消費させることができる。
- 割当はタスク→社員→実勤務工数として保持する。`AvailableHours`と`AllocatedHours`は実時間を整数で表す。
- 週を進めると、社員別の割当とプロダクトを`WeekProcessor`へ渡す。スキル・更新前の疲労・開始時の負債で補正した進捗が全タスクへ反映され、その後、新規完了タスクのプロダクトへの効果を合算して一度だけ適用する。更新後の負債は翌週から効く。
- 全タスクの処理後に各社員の`CompleteWeek()`を呼び、今週の消費勤務時間から疲労を更新してから利用可能工数を復元する。最後に割当をクリアし、週番号を進める。今週の稼働による疲労変化は翌週から効く。
- 無割当の社員も疲労の回復対象となる。社員の重複登録を入口で防ぎ、チームの利用可能工数の計上と週末更新を一人につき一度行う。
- 生産性の補正式とスキル対応表は別クラスで管理する。社員ごとの情報が失われるため、補正前にタスク単位で合算することはしない。
- 同一社員・同一タスクへの追加割当は実時間を加算する。完了済みタスクや残り勤務時間を超える割当は拒否し、失敗時の状態は変えない。
