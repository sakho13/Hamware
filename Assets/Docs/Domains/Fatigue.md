# Fatigue

疲労は社員の稼働量によって週ごとに変化する状態で、基本スキルとは独立して生産性へ影響します。

## 状態と計算

`Employee.Fatigue`は`decimal`の0〜100。通常の初期値は0で、コンストラクタの`initialFatigue`で範囲内の値を指定できます。範囲外は例外となり、公開setterはありません。

副作用のない`FatigueCalculator`が次の計算を担当します。

```text
実勤務時間 = WeeklyAvailableHours - AvailableHours
稼働率 = 実勤務時間 / WeeklyAvailableHours
翌週の疲労 = clamp(現在の疲労 + 40 × (稼働率 - 0.75), 0, 100)
疲労倍率 = 1 - 0.5 × (疲労 / 100)
進捗 = 実勤務時間 × 基本スキル倍率 × 疲労倍率
```

週40h勤務可能な社員は、無割当で-30、10hで-20、20hで-10、30hで変化なし、40hで+10となります。週の利用可能工数が異なっても、同じ稼働率なら疲労増減量は同じです。

疲労0/50/100の倍率は1/0.75/0.5。Backend: 4のみを持つ社員がBackendImplementationへ10h勤務した場合の進捗は、それぞれ12/9/6h相当です。スキルの値や実際の消費勤務時間は疲労で変わりません。

計算は`decimal`で行い、途中で端数を丸めません。計算への範囲外の疲労、0以下の週の利用可能工数、負または週の利用可能工数を超える実勤務工数は`ArgumentOutOfRangeException`で拒否します。

## 週次の更新順序

1. `WeekProcessor`が更新前の疲労と週送り時点のスキルで、全タスクの進捗を反映する。
2. `GameSimulation`が各社員の`CompleteWeek()`を一度ずつ呼ぶ。
3. 社員が消費勤務時間から翌週の疲労を更新し、利用可能工数をリセットする。
4. シミュレーションが割当をクリアし、週番号を進める。

今週の稼働による疲労変化は翌週から効きます。タスクの処理順や割当の分割数で結果は変わりません。無割当の社員も回復します。完了量を超えた進捗が破棄されても、消費済み勤務時間は疲労の計算対象になります。

たとえば基本スキル倍率1・疲労0の社員が40hずつ連続勤務すると、1週目の進捗は40、週末の疲労は10。2週目は疲労10で進捗38となり、週末の疲労は20になります。

## バランス調整

`FatigueCalculator`の`NeutralUtilization`(0.75)、`ChangePerUtilization`(40)、`MinProductivityMultiplier`(0.5)、`MinFatigue`(0)、`MaxFatigue`(100)で初期バランスを定義します。

残業、休暇、個別スキル、AI補正、スキル成長、UIは本機能の対象外です。
