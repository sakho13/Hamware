# Playable Prototype — R03

Hamware.unityをPlayするかビルドを起動すると、社員2名、機能4件、Testing2件、Architecture2件の固定シナリオで開始する。1ターンは1週間。基本スキルを持つ社員へ工数を割り当て、担当変更・休養・改善を試す。すべて完了しても休養と週送りを続けられる。職種属性・新タスク生成・依存関係・公開・保存は追加しない。

## 責務と依存関係

- Hamware.Game：Unityに依存しないドメイン。公開の割当API・週送り・不変レポートを提供する。
- Hamware.UI：Hamware.Gameを参照する別アセンブリ。ドメインのinternal APIにはアクセスできない。
- PrototypeScenario：固定シードデータを生成する。
- PrototypeSession：シミュレーションの開始・再開始と「計画中／週報確認中」を管理する。週報中の再確定・編集拒否はUIのPlanningFailureで表現する。
- HamwareUI：UI Toolkitによる表示・入力・確認。UIDocumentを必須コンポーネントとし、シーンにも保存する。
- PrototypePresentation：文言と表情の表示設定。休養の目安は各社員の勤務上限とFatigueCalculator.NeutralUtilization、タスクの効果文言はTaskProductProfilesの符号を参照する。

表情の切替60・休養を促す表示30はゲーム計算に影響しないUI設定としてPrototypePresentationに集約する。進捗・疲労・負債・品質の計算式をUIに持たせない。

週報を閉じるまで次の週を確定できない。前週の結果を再表示できる。「最初から」は確認ダイアログで保護する。シーンを開くエディタメニューは既存シーンを開くだけで、シーンの生成やビルド対象の上書きは行わない。

## 表示と検証

表示は1600×1000を基準に拡大縮小する。社員欄・タスク欄・週報はスクロール可能。日本語OSフォントを利用するため、試作対象は日本語環境のWindows。

UIEditModeテストは二重確定・週報中の編集拒否・再開始・アセンブリ境界・表示の参照元を確認する。PlayModeテストは割当編集、確認と週報、12週の疲労と回復、全件完了後の週送りと再開始に分割する。コントロールは社員・タスクのIdで特定し、現在パネルへ接続されているボタンへイベントを送る。取り外されたボタンへのイベントを連打防止の検証には使わない。

環境変数HAMWARE_CAPTURE_DIRを指定すると1600×1000と1280×720の画像を保存する。操作テストはUI ToolkitのClickEventによるもので、OSのマウス装置は経由しない。
